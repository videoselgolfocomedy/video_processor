# CLAUDE.md — Onboarding for a new session

> **Read this first when reopening the project.** It captures everything a
> new Claude session needs to be productive in 5 minutes instead of 50.

---

## 1. What this project is

**Standup Video Editor** — a local-first Next.js 14 app that turns raw
standup recordings (camera video + board audio) into finished material:
YouTube long-forms, vertical reels, subtitles, etc.

- Built for **El Golfo Comedy Club** sets recorded on iPhone (HEVC HDR)
  with separate board audio.
- Runs locally; projects are stored on the filesystem (no cloud DB).
- All heavy work (FFmpeg, Whisper, Demucs) runs server-side via the
  `JobManager` + Server-Sent Events for real-time progress.

GitHub: `videoselgolfocomedy/video_processor` (branch `main`).

---

## 2. Stack

- **Framework**: Next.js 14 App Router + TypeScript + Tailwind +
  shadcn-ui (always dark theme).
- **State**: Zustand stores (`project-store`, `compose-store`, `reel-store`,
  `job-store`).
- **Preview**: `@remotion/player` for in-browser video composition.
- **Render**: `ffmpeg-static` npm package (no system FFmpeg required).
- **Transcription**: Whisper (local), with optional reinterpretation via
  multiple LLM providers.
- **Audio**: Python scripts for voice subtraction (spectral / NLMS) and
  laughter detection; Demucs for stem separation.

---

## 3. Pipeline at a glance

```
.mov + board audio
        │
        ▼
  /import   →  upload + register sources                 (project-manager)
        │
        ▼
  /audio-prep → extract camera audio, optionally subtract voice,
                amplify board, mix preview, detect laughter
        │
        ▼
  /sync     →  align board↔camera, MUX video+chosen audio →
               muxed_TIMESTAMP.mp4                       (audio/mux/route.ts)
        │
        ▼
  /transcription → Whisper, segments, optional AI rewrite, bit detection
        │
        ▼
  /compose  →  cut clips on timeline, add cutaways, text overlays,
               per-clip motion (zoom/position), aspect ratio, subtitles
        │
        ▼
  /reels    →  generate 9:16 reels from compose bits
        │
        ▼
  /export   →  preset selection, range selector, FFmpeg render queue
```

Two key file types live in each project dir
(`projects/<id>/...`):

- `project.json` — single source of truth (composition state, subtitles,
  sources, sync info, reels, exports).
- `muxed_TIMESTAMP.mp4` (in `export/`) — synced video+audio source for
  every downstream step. Generated by the **mux** step. **All compose
  clip times reference this file's timeline**, not the raw camera.

## 4. Code map

### Frontend
- `src/app/project/[id]/<page>/page.tsx` — one page per pipeline step.
- `src/components/<feature>/` — UI components grouped by feature
  (`audio/`, `compose/`, `reels/`, `subtitles/`, `export/`, …).
- `src/stores/` — Zustand stores. The big ones are `compose-store.ts`
  (~1100 lines) and `reel-store.ts` (~900 lines). Both have full undo/
  redo, multi-select, and persistence to `project.json`.
- `src/hooks/use-sse.ts` — subscribes to job progress via SSE. **All
  callbacks must be `useCallback`'d** — inline arrow fns recreate the
  EventSource every render and spam the server.

### Server
- `src/server/project-manager.ts` — read/write `project.json`, resolve
  project subdirectories.
- `src/server/job-manager.ts` — singleton in-memory job tracker with
  pub/sub (drives SSE).
- `src/server/ffmpeg-wrapper.ts` — every FFmpeg invocation. The two
  big functions are `renderVideo()` (simple trim+subs) and
  `renderReelVideo()` (compose / reels with concat + transforms +
  overlays + ASS). Live-streams stderr with `[ffmpeg-render-reel]`
  prefix and has a 90s watchdog that SIGTERMs hung processes.
- `src/server/ass-generator.ts` — generates ASS subtitle files from
  `SubtitleSegment[] + SubtitleStyle`.
- `src/server/workers/` — long-running task workers (subtract,
  laughter, render, reinterpret, etc.).
- `src/app/api/projects/[id]/<thing>/route.ts` — thin API routes that
  delegate to the workers.

### Types
- `src/types/project.ts` — `ProjectState`, `CompositionClip`,
  `SubtitleSegment`, `ExportPreset`, etc. **Read this whenever in
  doubt about a field.**

## 5. Key concepts (read before touching code)

### `sourceInMs` vs `timelineStartMs`
- `sourceInMs/sourceOutMs` = position **inside the muxed video file**.
- `timelineStartMs/timelineEndMs` = position **on the compose timeline**
  (after cuts, gaps, etc.).
- The renderer uses `sourceInMs` to seek into the muxed file via `-ss`,
  and `timelineStartMs` only to compute the order/duration of clips.
- **When in doubt, look at `compose-store.ts`** — every clip operation
  preserves both values consistently.

### muxed video timeline
- After `mux`, all subtitles, clips, and reels reference time positions
  in the muxed file.
- The muxed file's duration equals the *aligned audio* duration; video
  is seeked forward by `videoSeekSec` if camera started before board.
- **Re-muxing does NOT lose work** — clips, subtitles, reels, etc.
  reference time-in-ms which stays valid as long as the new muxed file
  has the same duration (it does, audio drives duration).

### JobManager + SSE
- Every long task creates a `Job` with a UUID and emits progress events.
- Frontend subscribes via `useSSE({ jobId, onProgress, onComplete, onError })`.
- The route `/api/jobs/[jobId]/sse` streams JSON events and closes the
  connection when the job hits a terminal state.
- The job manager also kills processes via `setProcess()` so the user
  can cancel.

### Remotion preview vs FFmpeg render
- Remotion is **only for preview** in the browser. It mounts components
  (`Video`, `Audio`, `Sequence`) and renders frames live via `<Player>`.
- The actual export is **always FFmpeg**. Anything you build in Remotion
  must have an equivalent in `ffmpeg-wrapper.ts` — they don't share
  rendering code.

## 6. HDR colour handling — IMPORTANT

iPhone records in **HEVC 10-bit HLG BT.2020** (Dolby Vision Profile 8.4).
Any change to the color pipeline is a minefield. Lessons learned
(don't re-derive these the hard way):

1. **Mux always uses `-c:v copy`.** Re-encoding produces a tone-mapped
   file that doesn't match QuickTime's native HLG render → "washed out"
   complaints.
2. **Do NOT add `-color_range:v tv -colorspace:v bt709 -color_primaries:v
   bt709 -color_trc:v bt709`** to libx264 outputs. Forcing the output to
   claim plain SDR strips the HLG metadata that QuickTime uses to
   tone-map. The export looks worse than no tagging at all.
3. **Do NOT add `zscale + tonemap=hable` per-clip.** Custom tone-mapping
   produces different colors than QuickTime's built-in HLG render →
   user sees a mismatch with the source `.mov` viewed in QuickTime.
4. **The `youtube_1080_hdr` preset** uses libx265 → `yuv420p10le` with
   explicit `-color_range tv -colorspace bt2020nc -color_primaries
   bt2020 -color_trc arib-std-b67` and `-x265-params
   colorprim=bt2020:transfer=arib-std-b67:colormatrix=bt2020nc:range=
   limited`. This is the export that round-trips iPhone HDR faithfully.
5. **The default H.264 preset** is fine too — libx264 inherits the
   source's HLG tags onto the output H.264 stream; QuickTime tone-maps
   on playback. The output looks correct in QuickTime even though it's
   8-bit H.264 with HLG metadata. (Other players may not tone-map.)
6. **Browser previews of HLG content WILL look washed.** Browsers don't
   tone-map HLG. This is expected and unrelated to the export quality.
   If it ever blocks editing, the right fix is generating a small
   sidecar SDR proxy for the `<video>` element — NOT touching the mux.
7. **Dolby Vision metadata in .mov → .mp4** loses the `dvh1` tag and
   `dvcC` atom. QuickTime falls back to plain HLG render path → the
   muxed .mp4 looks subtly different from the .mov even though the
   HEVC stream is bit-identical. **Trying to preserve the tag with
   `-tag:v copy` + `.mov` container made the file unplayable in
   QuickTime** — image disappeared, only audio. Don't go down this
   path again without dedicated bitstream-filter handling.

**Rule of thumb when in doubt with color**: do nothing. Plain
`-c:v copy` mux + plain libx264 export is the working baseline.

## 7. FFmpeg pitfalls (we hit them all)

- **`format` is NOT an option of the `color` filter** in FFmpeg 6.x. Use
  the chain syntax: `color=...,format=yuv420p` (comma), not
  `color=...:format=yuv420p` (colon). The colon syntax throws "Option
  not found" and aborts.
- **`-c:v copy` with input seeking (`-ss` before `-i`)** snaps to the
  nearest keyframe BEFORE the target → audio/video desync up to 30s.
  For copy mode, use **output seeking** (`-ss` after `-i`). The mux
  route already does this.
- **Concat requires matching SAR/format/size** across all video inputs.
  When mixing `color=black` with real video, add `format=yuv420p` and
  `setsar=1` to both. Otherwise concat fails silently or with cryptic
  "Invalid argument" errors.
- **Keep a watchdog when spawning FFmpeg.** Already implemented in
  `renderReelVideo`: 90s of no stderr/progress activity → SIGTERM.
  Without this a malformed filter graph hangs forever at "Iniciando…".
- **Live-stream stderr to the console.** Already implemented with the
  `[ffmpeg-render-reel]` prefix. When something goes wrong, the actual
  error line is in there — searching that prefix in the dev server log
  is the fastest debugging step.
- **HEVC source has Dolby Vision RPUs** — FFmpeg prints "Multiple Dolby
  Vision RPUs found in one AU. Skipping previous." dozens of times.
  These are **harmless warnings**, not errors. Ignore them.
- **`Error opening memory font 'X.ttf'`** in libass output is also
  harmless — libass falls back to coretext to load the font from disk.

## 8. Common gotchas in the app code

- **Subtitles `words[]` array** can drift out of sync with the segment's
  `startMs/endMs` if a clamp/remap is done without updating words. See
  `splitByWords` in `subtitle-utils.ts` and `clampSegmentToBounds` —
  defensive code is in place but be careful when adding new mutations.
- **Compose autosave is debounced 3s.** Destructive ops save
  immediately. Right-click delete on reel tabs requires a confirm dialog
  — there is no X button (intentional, prevents accidents).
- **Reel video player** had a long history of feedback loops between
  the rAF tick and the seek effect. Solved with `lastTickSetMsRef` and
  `lastGapSeekSourceMsRef` — don't replace those refs with booleans
  thinking it's "cleaner". The value-based comparison is what makes it
  race-free.
- **Compose v1/a1 tracks are protected** — `addClip`/`removeTrack` etc.
  refuse to delete them. The auto-populate in `loadComposition` recreates
  them on load.
- **Per-clip `transform: { scale, x, y }`** is the Premiere-style motion
  feature. Applied as CSS transform in Remotion preview AND as
  `scale + overlay` on a black canvas in the FFmpeg renderer (only
  when at least one clip has a non-identity transform — otherwise the
  original simple pipeline is used to preserve color characteristics).

## 10. How to debug a stuck export (recipe)

1. Open the dev server log. Search `[ffmpeg-render-reel]`.
2. The first line after the spawn is the full FFmpeg command. Copy it
   to a terminal to reproduce manually.
3. If FFmpeg printed `Error applying option 'X' to filter 'Y'` → filter
   graph syntax bug. See § 7 above.
4. If FFmpeg printed nothing for ≥90s the watchdog will fire and kill
   it. The error message in the export queue will contain the last 3
   stderr lines.
5. If the filter graph is too complex to read inline, split it on `;`
   and re-indent each subgraph.

For mux issues, the equivalent prefix is `[mux]`. Same drill.

## 11. How to start a new session productively

1. **Read this file first.** (You're doing it.)
2. Run `git log --oneline -20` to see what was changed recently. The
   commit messages are detailed — they explain *why*, not just *what*.
3. If the user mentions a specific feature, look at the matching folder
   under `src/components/` and the matching store under `src/stores/`.
4. If the user mentions a specific file format / color / encoding
   issue, **re-read § 6 before touching anything**.
5. Before changing the FFmpeg pipeline, **read the current
   `renderReelVideo` end-to-end**. The dual pipeline (transform vs
   no-transform) is subtle.
6. Save the user's time: when in doubt, paste the `[ffmpeg-render-reel]`
   stderr lines back to them and ask, instead of guessing at colorspace
   parameters. Several wasted commits in the history could have been
   avoided this way.

## 13. Project portability — moving / archiving a project

A project is the directory `projects/<uuid>/` next to the repo. Each
sub-directory has a different role:

| Path | Essential? | Notes |
|---|---|---|
| `project.json` | ✅ **YES** — single source of truth (cuts, subs, reels, styles, versions, exports). ~100-200 KB. | Without this you start from scratch. |
| `source/` | ✅ **YES** — raw uploads (camera `.mov`, board `.mp3`/`.wav`). Typically GB-scale. | Without these the muxing / transcription / alignment can't be redone. |
| `audio/` | ⚠ Useful — derived audio (extracted camera, aligned ambient, mix variants, amplified). ~1 GB. | Drop to save space, but the user has to re-run extract → align → mix → amplify, which takes 5-15 min. |
| `export/muxed_*.mp4` | ⚠ Useful — the synced video referenced by every downstream step. ~1-2 GB. | Drop to save space, but you'll have to re-mux (~30 s for SDR, several min if HDR re-encode is enabled). |
| `export/*.mp4` (renders) | ❌ Drop — final renders. | Re-derived from `project.json` + muxed file. |
| `export/*.ass`, `export/debug_*` | ❌ Drop — generated per render. | Auto-recreated. |
| `compose/`, `transcription/` | ⚠ Sometimes empty, sometimes hold media-bin extras (cutaways, image overlays). Copy if non-empty. | |

### Minimum bundle to move a project to another machine

```
projects/<uuid>/
  project.json
  source/<all files>
```

After copying, on the new machine:
1. Drop the directory under `projects/` next to a clean checkout of
   `videoselgolfocomedy/video_processor`.
2. `npm install && npm run dev`
3. Open the project in the UI. Everything (cuts, subs, reels, styles)
   loads from `project.json`.
4. Re-run **Sync & Mix → Mux** to regenerate `muxed_*.mp4`. Compose
   clip times reference muxed timeline; they stay valid because the
   audio drives duration.
5. (Optional) Re-extract camera audio, re-align, re-mix if you want
   the working audio files back.

### Full bundle (no rebuild needed on the other side)

Add `audio/` and `export/muxed_*.mp4`:

```
projects/<uuid>/
  project.json
  source/...
  audio/...
  export/muxed_*.mp4
```

This is what to copy if you want to move the project AND open it
ready to edit/export immediately.

### Lightweight cloud backup (no media)

UI button "Backup" → `/api/projects/[id]/backup` produces a zip with:
- `project.json` (paths sanitized to relative)
- `export/*.srt`, `export/*.ass`
- `compose/` files <10 MB
- Fonts matching the subtitle style

It does **NOT** include source video, source audio, working audio, or
muxed file. Useful for transferring just the *state* — you'll re-upload
the media on the other side. The matching `POST /api/projects/[id]/backup`
restore route recreates the project from such a zip.

### What's safe to delete to free up disk space

If a project is "done" (you've shipped the renders) and you want to
keep it editable:
- Delete `export/*.mp4` renders → ~hundreds of MB to GBs reclaimed.
- Delete `export/debug_*.ass` → trivial.
- Keep `export/muxed_*.mp4`, `audio/`, `source/`, and `project.json`.

If a project is fully archived (you don't expect to re-edit, just
keep the result):
- Keep ONLY the rendered output(s) you care about.
- Delete the whole `projects/<uuid>/` directory.
